# Безопасность

## Ключевые правила

- Один клиентский профиль предназначен только для одного устройства.
- Один device slot имеет один уникальный client identity.
- Root CA не хранится на VPN-сервере.
- Invite-токены хранятся только в hash-виде.
- Download links должны быть короткоживущими.
- Все действия с устройствами пишутся в audit log.

## Анти-шаринг

Файлы профилей нельзя сделать полностью некопируемыми. Поэтому защита строится вокруг серверной политики:

- уникальный client certificate на слот;
- `unique = keep` в strongSwan;
- новый одновременный сеанс с тем же identity отклоняется;
- действующий сеанс не выбивается новым подключением;
- попытки повторного использования логируются.

## PKI

MVP использует dev PKI через OpenSSL.

Продуктовая версия должна использовать:

- offline root CA;
- issuing intermediate CA;
- audit выпуска сертификатов;
- CRL или OCSP-like policy propagation;
- защищенное хранение intermediate key.

## Что не логировать

- содержимое трафика;
- посещаемые сайты;
- DNS-запросы пользователей;
- приватные ключи;
- пароли PKCS#12 в application logs.

## Что можно логировать

- slot id;
- identity;
- certificate serial;
- последнюю активность;
- суммарный трафик;
- duplicate connection attempts;
- ошибки аутентификации.
